# TDD Report: G1-M4 — Pipeline Vertex への ResourceClaim 自動注入

**Plan**: `.claude/plans/g1-m4.plan.md`
**Branch**: `feature/g1-m4-pipeline-vertex-resourceclaim`
**Date**: 2026-06-29

---

## 1. User Journeys

1. **Pipeline オペレータとして**、`gpu-direct-comm.numaproj.io/numa-network-edges` annotation を Pipeline に付与するだけで、対象 vertex の `spec.resourceClaims` に RCT 参照が自動注入される。これにより numaflow の既存コードを改変せずに DRA による Secondary NIC 割り当てが有効になる。

2. **既存 Pipeline オペレータとして**、annotation を付与していない Pipeline は従来通り変更なく作成・更新でき、Mutating Webhook による意図しない変更を受けない。

---

## 2. Task Report

### Task 1: Mutating Webhook ハンドラの実装

**Testing Policy**  
`PipelineMutator.Handle` の正確性を保証するために、以下の側面を unit test で検証する必要があった：
- annotation 不在の場合の素通り（既存 Pipeline への非破壊性）
- `connectionType: direct` の束縛で `from`/`to` 両 vertex への注入
- 同一 vertex が複数束縛に現れる場合の重複排除
- 既存 `resourceClaims` がある vertex への追記（既存エントリ消去の防止）
- `connectionType: direct` 以外の束縛のスキップ

これら 5 ケースは ADR-0009 の設計仕様に直接対応しており、実装のコーナーケースを網羅する。

**再現手順**

```bash

  -l numaflow.numaproj.io/isbsvc-name=default \
  -n default --timeout=120s

kubectl apply -f samples/g1m4_pipeline_with_binding.yaml

# 3. annotation なし Pipeline を apply
kubectl apply -f samples/g1m4_pipeline_no_annotation.yaml
```

**Execution Log**

annotation 付き Pipeline の resourceClaims を確認：

```

  "resourceClaims": [
    {
      "name": "pipeline1-multi-network-rct",

  "name": "inference",

  ]

```

`filter-resize` と `inference` の両 vertex に `pipeline1-multi-network-rct` が注入された。

annotation なし Pipeline の確認：

```

  | jq '.spec.vertices[] | {name: .name, resourceClaims: .resourceClaims}'

  "name": "source-vertex",
  "resourceClaims": null
}
{
  "name": "sink-vertex",
  "resourceClaims": null
}
```

annotation のない Pipeline には `resourceClaims` が注入されず、非破壊性が確認された。
